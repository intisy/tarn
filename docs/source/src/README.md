The checker, `tarn-check`. `check_tree` reads the version file to tell a repo docs tree (`docs/VERSION`, rooted at `docs/`) from an org docs tree (a root `VERSION`, rooted at the repo root), finds every source folder that holds code, regenerates the marked blocks of the descent tree (with `--write` it rewrites the stale ones first, so the walk reads the fresh files), walks the descent tree folder by folder, checks every descent file against the repos snapshot when `--snapshot` and `--repository` give one (and warns once that it did not when they do not), warns about the drift a single push cannot see (an org whose repos changed, an older declared version, a `source/` doc its code has outrun), and adds each finding to a report as `refused|warned <path>:<line> <rule> <text>`, where line 0 means the whole file or folder. Every path is relative to the repo root with forward slashes, and every name is compared byte for byte with the real directory entry, so a case mismatch is caught on a case-insensitive disk too. The program exits 0 when nothing is refused, 1 when something is, and 2 on bad usage; with `--quick` it skips the git staleness calls and nothing else, and with `--warn-only` it prints every finding, refused and warned, and exits 0 whatever was found, which is the scheduled run's mode, so the issue it keeps carries a refusal an outside change caused. `tarn-check adopt` is the other command: it plans the files a repo or an org docs repo needs to follow the standard (the version file, README skeletons whose prose reads `to write` for every descent folder that lacks one, the filled `source-children` or `org-repos` blocks, and the thin workflow caller, which passes the `TARN_TOKEN` secret), prints one `create` or `keep` line per file, and with `--write` creates the absent ones, never touching a file that exists; it refuses a repo that declares the other kind of tree, a version file that is not tarn's, and a folder it would write into that exists only under another case.
