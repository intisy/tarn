The tests. Each folder under `tests/trees/` is one fixture: a whole mini repo with its own version file, named for the case it proves, and one ctest test per fixture runs `check_test`, which checks that tree and compares the exact report and exit code with the expectation written for it in `check_test.c`. Before any case runs, `prepare_trees.cmake` copies the fixtures into the build folder and renames two kinds of file, so tarn's own checker and git never read a fixture as tarn's: a name ending in `.fixture` loses that suffix (fixture code files, which would otherwise demand a `source/` doc here), and a name starting with `dot-` starts with `.` instead (a fixture's `.gitignore`, which git would otherwise apply to tarn). The `crlf-bom` fixture is kept CRLF in git by `.gitattributes`, and the `directory-link` fixture gets its folder link (a junction on Windows, a symlink elsewhere) only at that step, which fails if the link cannot be made. Beside the fixtures, `expect_exit.cmake` runs `tarn-check` on four command lines and asserts each exact exit code (0, 1, 2 and 2), and `self` runs `tarn-check` on this repo.

- [CMakeLists.txt](../../../tests/CMakeLists.txt) - the test registrations: the preparing step, one test per fixture, the command line, and the self check
- [expect_exit.cmake](../../../tests/expect_exit.cmake) - runs `tarn-check` with one argument and fails unless it exits with the expected code
- [check_test.c](../../../tests/check_test.c) - the runner and the expected report of every fixture
- [prepare_trees.cmake](../../../tests/prepare_trees.cmake) - the copy of the fixtures into the build folder, with the two renames and the folder link
