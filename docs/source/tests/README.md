The tests. Each folder under `tests/trees/` is one fixture: a whole mini repo with its own version file, named for the case it proves, and one ctest test per fixture (`check/<case>`, and `generate/<case>` for a write case) runs `check_test`, which checks that tree and compares the exact report and exit code with the expectation written for it in `check_test.c`. Before any case runs, `prepare_trees.cmake` copies the fixtures into the build folder and renames two kinds of file, so tarn's own checker and git never read a fixture as tarn's: a name ending in `.fixture` loses that suffix (fixture code files, which would otherwise demand a `source/` doc here), and a name starting with `dot-` starts with `.` instead (a fixture's `.gitignore`, which git would otherwise apply to tarn). The `crlf-bom` fixture is kept CRLF in git by `.gitattributes`, and the `directory-link` fixture gets its folder link (a junction on Windows, a symlink elsewhere) only at that step, which fails if the link cannot be made. The write cases live apart under `tests/write-trees/`, copied the same way into their own build folder so a rewrite never touches the check fixtures: each holds a stale tree and an `expected/` folder with the files as they must read afterwards, and `generate_test` regenerates it, compares the report, compares each listed file byte for byte (the `write-crlf-bom` case keeps CRLF and a BOM through the rewrite), then checks the result again. Beside the fixtures, `expect_exit.cmake` runs `tarn-check` on four command lines and asserts each exact exit code (0, 1, 2 and 2), `expect_write.cmake` runs `--write` on a copy of a write case and asserts exit 0 and the regenerated file, and `self` runs `tarn-check` on this repo.
