The definitions of version 1: one file per kind of file a docs tree may hold. Each says what the kind is for, who reads it, whether it is current (pruned when a fact stops applying) or a record (kept as written), its rules, and where it may appear. A file is allowed only if it is one of these kinds.

- [folder-readme.md](folder-readme.md) - the README of every folder, the one accepted form of a child line, and the `to write` placeholder
- [architecture.md](architecture.md) - how the parts fit and talk, the top of a descent tree
- [category.md](category.md) - a category folder, its prose files, the size budget for descent files, and the repos snapshot the cross-repo rules read
- [source.md](source.md) - the source mirror: one doc per source folder that holds code
- [content.md](content.md) - the root CONTENT.md the top-level README is generated from
- [generated.md](generated.md) - generated blocks and the marker that delimits them
- [version.md](version.md) - the version files, the pin rule, how a version ships, and adopting the standard in one step
- [faq.md](faq.md) - the questions asked, linked to the docs that answer them
- [rules.md](rules.md) - the standing rules of a layer, each with its grounds
- [tasks.md](tasks.md) - the queue of every task a layer has ever had
- [decisions.md](decisions.md) - the log of rulings with their grounds
- [handoff.md](handoff.md) - where work stands now, so a cold session can resume
- [plans.md](plans.md) - approved plans for building a spec
- [specs.md](specs.md) - approved designs, one dated file each
- [records.md](records.md) - finished execution records and measurements
